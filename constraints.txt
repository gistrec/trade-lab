# Pinned transitive dependency set. Applied with `-c` by BOTH CI
# (.github/workflows/ci.yml) and deploy.sh, so the versions the test suite
# runs against are the versions the real-money order path imports.
#
# Why this file exists: dependencies are declared with lower bounds only
# (ccxt>=4.0), so every unconstrained install resolved to whatever was
# current that day. On 2026-08-30 three ccxt versions were in play at
# once — 4.5.56 in the dev venv where tests ran, 4.5.74 on the box placing
# real orders, 4.5.76 from a fresh resolve. ccxt releases almost daily and
# changes order params, sandbox URLs and error handling; "execution must
# replicate the backtest" cannot hold on an environment nobody pinned.
#
# Regenerate deliberately, in its own commit, and let CI run the suite
# against the new set BEFORE deploying:
#
#   uv pip compile pyproject.toml --all-extras --universal \
#       --python-version 3.11 --no-header --output-file constraints.txt
#
# --universal keeps one file valid for macOS dev and Linux server; the
# 3.11 floor matches requires-python, and markers cover the 3.11-3.13 CI
# matrix (see the numpy split below).
